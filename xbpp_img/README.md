# Display-test framebuffer assets

The raw files and PNG previews mirror the six frames generated by
`src/display.cpp`: palette/checkerboard, black, white, yellow, red, and
orientation. The firmware still draws the frames dynamically; it does not load
these files from the folder.

Each raw framebuffer has a matching PNG whose name is the raw filename with
`.png` appended. For example:

- `palette_test_212x104.2bpp`
- `palette_test_212x104.2bpp.png`

## Pixel formats

Both raw formats have no header.

- `.1bpp`: one bit per pixel, left-to-right and top-to-bottom, most-significant
  bit first. Rows are padded to `(width + 7) / 8` bytes; padding bits are white.
  Bit `0` is black and bit `1` is white. Non-black test colors map to white,
  matching the firmware's monochrome framebuffer.
- `.2bpp`: pixels are packed left-to-right and top-to-bottom, with the first
  pixel in bits 7-6, followed by bits 5-4, 3-2, and 1-0. The payload is
  `width * height / 4` bytes.

The 2bpp logical palette is:

| Index | Logical color | PNG RGB |
|---|---|---|
| `00` | Black | `#000000` |
| `01` | White | `#FFFFFF` |
| `10` | Yellow | `#FFFF00` |
| `11` | Red | `#FF0000` |

PNG files decode the logical framebuffer values. A panel driver may map those
values to different physical colors; for example, the WFT042 path maps logical
yellow to red.

## Screen configurations covered

Each listed bit-depth combination has all six frames and a corresponding PNG
preview for every raw file.

| Resolution | Framebuffer formats | Raw bytes per frame |
|---|---|---:|
| 212 x 104 | 2bpp | 5,512 |
| 250 x 128 | 2bpp | 8,000 |
| 296 x 128 | 1bpp | 4,736 |
| 400 x 300 | 1bpp, 2bpp | 15,000 / 30,000 |
| 648 x 480 | 1bpp | 38,880 |
| 800 x 480 | 1bpp | 48,000 |
