# Display-test framebuffer assets

The raw files and PNG previews mirror the frames generated by `src/display.cpp`.
Most configurations use six frames: palette/checkerboard, black, white, yellow,
red, and orientation. The E6 configuration uses eight frames, adding blue and
green solid-color screens. The firmware still draws the frames dynamically; it
does not load these files from the folder.

Each raw framebuffer has a matching PNG whose name is the raw filename with
`.png` appended. For example:

- `palette_test_212x104.2bpp`
- `palette_test_212x104.2bpp.png`

## Pixel formats

Both raw formats have no header.

- `.1bpp`: one bit per pixel, left-to-right and top-to-bottom, most-significant
  bit first. Rows are padded to `(width + 7) / 8` bytes; padding bits are white.
  Bit `0` is black and bit `1` is white. Non-black test colors map to white,
  matching the firmware's monochrome framebuffer.
- `.2bpp`: pixels are packed left-to-right and top-to-bottom, with the first
  pixel in bits 7-6, followed by bits 5-4, 3-2, and 1-0. The payload is
  `width * height / 4` bytes.
- `.4bpp`: pixels are packed left-to-right and top-to-bottom, with the first
  pixel in the high nibble and the second in the low nibble. The payload is
  `width * height / 2` bytes. GDEH037E01 raw files use the controller's native
  720 x 480 landscape scan order; their PNG previews show the logical 480 x 720
  portrait image. Logical pixel `(x, y)` is packed at pixel index
  `(479 - x) * 720 + y` to match the tested panel orientation.

The 2bpp logical palette is:

| Index | Logical color | PNG RGB |
|---|---|---|
| `00` | Black | `#000000` |
| `01` | White | `#FFFFFF` |
| `10` | Yellow | `#FFFF00` |
| `11` | Red | `#FF0000` |

The GDEH037E01 E6 4bpp nibble codes follow its JD7601 reference example:

| Nibble | Logical color | PNG RGB |
|---|---|---|
| `0x0` | Black | `#000000` |
| `0x1` | White | `#FFFFFF` |
| `0x2` | Yellow | `#FFFF00` |
| `0x3` | Red | `#FF0000` |
| `0x5` | Blue | `#0000FF` |
| `0x6` | Green | `#00FF00` |

PNG files decode the logical framebuffer values. A panel driver may map those
values to different physical colors; for example, the WFT042 path maps logical
yellow to red.

## Screen configurations covered

Each listed bit-depth combination has all of its firmware test frames and a
corresponding PNG preview for every raw file. E6 has eight frames; other
configurations have six.

| Resolution | Framebuffer formats | Raw bytes per frame |
|---|---|---:|
| 212 x 104 | 2bpp | 5,512 |
| 250 x 128 | 2bpp | 8,000 |
| 296 x 128 | 1bpp | 4,736 |
| 400 x 300 | 1bpp, 2bpp | 15,000 / 30,000 |
| 648 x 480 | 1bpp | 38,880 |
| 800 x 480 | 1bpp | 48,000 |
| 480 x 720 | 4bpp | 172,800 |
